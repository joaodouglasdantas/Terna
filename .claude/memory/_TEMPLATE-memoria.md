> **Como usar este template.** Copie este arquivo para um novo nome (ex:
> `feedback_envio_idempotente.md`), preencha o frontmatter e o corpo, e registre uma linha
> no índice `MEMORY.md`. Apague este bloco de instruções no arquivo final.
>
> **Tipos válidos (`metadata.type`):**
> - `user` — perfil/papel/preferências de quem trabalha no projeto.
> - `feedback` — orientação de como conduzir o trabalho (o que evitar / o que repetir).
> - `project` — contexto de iniciativas, decisões, incidentes (muda rápido — date tudo).
> - `reference` — ponteiros para sistemas externos (onde achar X).

Conteúdo da memória aqui.

Para `feedback` e `project`, estruture assim:

- **Regra/fato:** o ponto central, direto.
- **Why:** o motivo (incidente passado, restrição, preferência forte) — ajuda a julgar
  casos de borda em vez de seguir a regra cegamente.
- **How to apply:** quando/onde isto se aplica.

Vincule memórias relacionadas com `[[outro-slug]]`.
