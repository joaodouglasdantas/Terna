⚙️ Harness 2.5.0 MELHORIAS 1-4 APROVADAS

Continuação da 2.4.0, publicada no mesmo dia (30/07/2026) — as 4 melhorias que você aprovou, implementadas na cópia-mestre.

🔧 As 4 mudanças

1️⃣ Ciclos de review: base 2 + escalada inteligente

Preset agora resolve a base (econômico 1 · equilibrado 2 · máximo 3). Esgotou a base? +1 ciclo automático SÓ se estiver convergindo (último ciclo corrigiu bloqueante e ainda resta 🔴). Estagnou → gate direto, sem queimar ciclo. Vale para Codex review, beholder e michelangelo.
antes (default)
4 ciclos
agora (base)
2
escalada (se convergindo)
+1

Número explícito no Perfil = limite duro sem escalada (opt-out). Dados: ciclos 3-4 quase só caçavam 🟡, a ~16min/ciclo. ≈ −30-50min/PRD

2️⃣ Michelangelo em paralelo com o review

Na /prd-exec, o gate de UX da tela construída (Fase 2.9) é disparado na mesma mensagem do ciclo 1 do review dupla-cega — a tela já existe (acceptance passou) e UX não depende de review de lógica. Triagem continua depois da Fase 2 fechar; correção que tocou UI auditada → revalidação pontual.
review → depois UX (serial)→codex + sherlock + michelangelo juntos

≈ −6-20min de caminho crítico nas PRDs com UI.

3️⃣ /harness-report — o radar de custo

Skill nova que cruza a telemetria já gravada (prds/_metrics/harness-runs.jsonl): mediana/p90 de duração ativa, tokens, ciclos, espera humana e negações por tipo de execução. --all varre todos os projetos irmãos; réguas 🔴/🟠 de regressão + tendência vs janela anterior; --html gera página visual.
degradação vista quando dói→curva subindo detectada em semanas

Hábito novo: /harness-report --all 1x/mês, rodado do vault.

4️⃣ Cache de discovery por módulo

prds/_discovery-cache/<modulo>.md guarda o mapa reutilizável (schema + código + precedentes) com commit e paths. PRD nova no mesmo módulo: se git log mostra que nada tocou os paths (e o cache tem <30 dias), pula os Agents B e C. A (DTs), tony-stark e atlas rodam sempre — dependem do escopo novo.
re-mapear schema/código toda PRD→metade do discovery pulada em PRDs sequenciais
