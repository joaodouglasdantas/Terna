🔧 As 7 mudanças

corte

1. Acceptance sem hefesto

A penúltima task (specs E2E) é executada direto pela sessão pai — o subagente que rodava a suite e era conferido de novo morreu.
hefesto 51-85min + re-run→1 execução da pai
corte

2. Roadmap HTML opt-in

Skip HTML Roadmap ausente agora significa pular o HTML interativo. Só gera com Nao explícito na PRD.
HTML em toda PRD→só quando você pedir
modelo

3. Refino em Sonnet (ciclos 2+)

sherlock, beholder e michelangelo usam o modelo do preset só no ciclo 1. Ciclos 2+ (conferir correções pontuais) = Sonnet sempre + releitura só do que mudou. Codex: high→medium.
4× Opus relendo tudo→1× preset + refinos baratos
fluxo

4. Entrevista única (3 skills)

/prd 0.1 · /prd-exec 0.3 · /dt-exec 1.4 — todas as decisões numa AskUserQuestion no início; os gates do meio consultam as respostas em vez de parar. /prd em modo TURBO: 1 aceite no final.
15 paradas possíveis→1 entrevista + 1 aceite
contexto

5. PERFIL-RESUMO.md

Destilado ~2KB do Perfil (fatos operativos). Todos os subagentes leem o resumo; fallback pro completo. Última task de toda PRD mantém a sincronia.
22KB × ~30 subagentes→2KB × ~30
escrita

6. Tasks por CONTRATO

Código completo só em componente de risco (migration, SQL, regex, integração). O rotineiro vira contrato (assinatura + regras + critérios) referenciando a Técnica. O código nasce 1 vez.
código no doc + no repo→contrato no doc, código no repo
infra

7. Hooks mais baratos + watchdog

Hooks RAG com early-exit ANTES do source (rag-inject rodava globs de PHP em TODO prompt, síncrono, mesmo com RAG off). external-review ganhou watchdog portável — no Git Bash/Windows o Codex rodava sem teto nenhum.
custo por turno + review sem limite→no-op real + teto garantido
🛡️ O que NÃO mudou: safe-mode, review dupla-cega obrigatório, gate anti-alucinação (saída bruta colada), fechamento documental das duas pontas, teto anti-degeneração dos gates, e as paradas estruturais (safe-mode reprovado, >10 bloqueantes no ciclo 1, falha não-recuperável). O corte foi de repetição e espera, nunca de rede de segurança.

🔮 Próximas 5 melhorias sugeridas

1. Ciclos default 4 → 2 (com escalada)

IMPACTO ALTO · ESFORÇO BAIXO

Ainda não mexi (você não pediu): o default segue 4. Os dados mostram que ciclos 3-4 quase só caçam 🟡. Proposta: default 2, e um 3º ciclo só se o 2º ainda tiver 🔴 — economiza ~30-50min/PRD por cima do que a 2.4.0 já corta.

2. Fase 2.9 em paralelo com a Fase 2

IMPACTO MÉDIO · ESFORÇO BAIXO

O michelangelo audita a tela construída só DEPOIS do review de código fechar — mas UX de tela não depende de review de lógica. Rodar os dois juntos tira ~6-20min do caminho crítico das PRDs com UI.

3. Telemetria comparativa automática

IMPACTO MÉDIO · ESFORÇO MÉDIO

O harness-metrics já grava prds/_metrics/harness-runs.jsonl por projeto, mas ninguém olha o agregado. Um /harness-report mensal (no vault) cruzando duração×tokens×ciclos×preset por projeto mostraria regressões de custo em dias, não semanas — teria pego essa degradação lá atrás.

4. Cache de discovery entre PRDs do mesmo módulo

IMPACTO MÉDIO · ESFORÇO MÉDIO

PRDs seguidas no mesmo módulo re-mapeiam o mesmo schema/código do zero (B e C de novo). Um _discovery-modulo.md com validade (invalidado por migration/commit no módulo) deixaria PRDs sequenciais pularem metade do discovery.

5. Perfis de execução noturna (fila de PRDs)

IMPACTO ALTO · ESFORÇO ALTO

Com a entrevista única, uma execução vira 100% autônoma após a decolagem. Próximo degrau: enfileirar 2-3 PRDs aprovadas e rodar de madrugada (allowlist já resolve permissão; entrevista colhida de dia; relatório de manhã via WAHA). O wall-clock deixa de competir com o seu expediente.
